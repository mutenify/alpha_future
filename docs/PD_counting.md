# PD model v1

Единственный исполняемый эталон параметров — миграция
`backend/migrations/000004_ui_and_scoring_rules.up.sql`. Python-зеркало для
валидации находится в `ml/app/model.py`, а Go-реализация — в
`backend/internal/scoring`.

## Scorecard

Модель использует восемь числовых факторов (`age_months`, `overdues12m`,
`max_overdue_days`, `inquiries3m`, `tax_debt`, `revenue_trend`, `revenue_cv`,
`debt_load`) и категориальный `okved_group`. Интервалы имеют вид
`(lower, upper]`; точные баллы версионируются в таблицах `scorecard_models` и
`scorecard_bins`.

Параметры версии `v1`:

- `BaseScore = 600`;
- `BaseOdds = 50`;
- `PDO = 20`;
- `score` — сумма одного совпавшего бина каждого фактора, без дополнительного
  прибавления `BaseScore`.

Вероятность дефолта:

```text
PD = 1 / (1 + BaseOdds × 2 ^ ((score − BaseScore) / PDO))
```

Больший score означает меньшую PD. `debt_load = D_old / μ`, где `D_old` —
ежемесячные платежи по существующим обязательствам.

## Маршрутизация

Пороговые значения являются частью кредитного продукта, а не scorecard:

- `PD > 0.25` → `REJECTED`;
- `0.10 ≤ PD ≤ 0.25` → `MANUAL_REVIEW`;
- `PD < 0.10` и запрошенный платёж проходит оба лимита → `APPROVED`;
- `PD < 0.10`, платёж не проходит, но существует POINT_A или POINT_B →
  `COUNTER_OFFER`;
- если безопасного альтернативного оффера нет → `MANUAL_REVIEW`.

Стоп-факторы `LIQUIDATION`, `BANKRUPTCY` и `ACCOUNTS_BLOCKED` дают отказ до
расчёта score/PD. Недоступность источника после исчерпания повторов переводит
заявку в `MANUAL_REVIEW`.

Исторические ноутбуки первоначально использовали другую четырёхфакторную карту
и пороги 5%/15%. Эта версия не совместима со схемой БД и не является рабочим
эталоном; ноутбуки обновлены и теперь импортируют модель `v1`.
